# Agent-ready UI skills: initial update

## Accepted scope

The owner approved updating and evaluating the Yogurt skills as part of the component replacement. Update the existing build and review entries for the opt-in Web bridge; retain their existing routing, installed-pin checks, original user intent and product ownership. Additional renderer-specific guidance requires separately observed support.

## Contract

- A user-requested agent-operated Web surface resolves the installed SDK and checks its published agent entry and supported controls before using them. A missing entry or unqualified Native target is reported rather than invented.
- A consuming product supplies its own action policy, disclosure scope, confirmation and service authorization. An action policy alone does not filter observations. Importing a UI component must not be presented as creating a connection or granting an agent authority.
- A review distinguishes source and local fixture observations from an actual model, a running Native target or product service. It checks allowed and refused operations and confirms observed state rather than claiming all effects were rolled back after a partial action.
- Keep skill entries short, preserve existing workflow and independent feedback boundaries, and add no new external action authority.

## Evidence

Validate skill frontmatter and existing deterministic evaluation tests. Exercise a synthetic installed Web fixture for agent control and denial independently from a model. Record model-driven activation separately from reliable routing across the evaluation set, cost optimization, Native runtime and production effects.

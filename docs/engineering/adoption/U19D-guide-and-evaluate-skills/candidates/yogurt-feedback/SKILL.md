---
name: yogurt-feedback
description: Triage a Yogurt gap, a reusable pattern proposal or a request to file a design-system issue. Resolve product versus SDK ownership, existing reports and the authorized GitHub action.
---

Read the affected pin, target, component or pattern and expected user behavior. Check the same public entry in a minimal consumer. Product data, navigation and permissions belong to the product. A shared interaction defect or missing supported capability belongs to Yogurt. For a suggested preset, compare actual consumer examples and identify what remains local.

Prepare the smallest report another maintainer can use. Include owner and repository, pin, renderer, public ID, steps, expected and actual results, impact and a test for a fix. Share only the context cleared for that destination. Keep an incomplete reproduction labeled as a proposal or an unconfirmed finding.

Search open and closed issues by public ID, symptom and renderer. Return an existing issue when it covers the case. Use the configured destination and act within the caller's authorization to create or update. A draft request produces a draft. A missing binding or write permission produces a portable draft with the missing detail.

After a successful write, return the canonical issue reference. If the create response is lost, search again and reconcile the exact report. If its existence is still unknown, keep the draft pending. A retry must preserve the original request identity.

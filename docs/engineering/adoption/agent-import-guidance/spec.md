# Agent import guidance: web lookup

## Accepted scope

The owner requested evaluated, efficient skills that use the installed SDK. A model-driven consumer fixture attempted to import two separate components from one entry even though their declaration module was shared. This scoped improvement makes each resolved Web entry directly reusable and keeps the existing lookup fields and Native response compatible.

## Contract

- For every resolved Web component, emit a copyable named import statement derived only from that installed entry and its declared re-export names. Keep `id`, `entry`, `names` and `types` unchanged. Do not combine components solely because they share a declaration module.
- The build skill directs an agent to copy each statement exactly and resolve any additional component before use. It does not grant network, file-write, product-action or service authority.
- A missing, invalid or unsupported installed declaration still fails closed. Native lookup data remains unchanged.

## Evidence

Against an installed SDK fixture, resolve the review and request patterns and verify distinct statements for components sharing a declaration file. Dynamically import each resolved entry and verify its declared names exist without creating an agent bridge. Exercise existing plugin resolution tests and skill validation. A model-driven retry is a separate, bounded observation; one success would not establish reliable activation or cost optimization.

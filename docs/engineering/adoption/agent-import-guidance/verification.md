# Agent import guidance evidence

One small-model decision-flow trial loaded the build skill and failed before the UI could mount: its answer imported `Result` from the `Status` entry. The installed lookup had supplied separate entries, but both shared a declaration file. The remaining flow assertions were not observed. The attempt took 59.669 seconds and reported 94,715 input tokens, including 75,648 cached tokens, and 2,560 output tokens. Its actual monetary charge was unavailable.

The revised lookup emits separate, copyable statements. An installed Web fixture checked six resolved statements against their actual ESM exports, rejected an unknown ID and exercised both Vite and Next.js consumers. The Native lookup returned its existing template binding. The changed skill passed frontmatter validation and sixteen deterministic evaluation tests passed.

A single repeat with the revised guidance built successfully and passed the cancellation and confirmation checks. It still failed the recovery check because the generated screen added a second lookup button alongside the one already supplied by `Receipt`. No receipt lookup occurred, and the last assertion was not observed. That attempt took 58.888 seconds of model time and reported 78,950 input tokens, including 59,008 cached tokens, and 2,616 output tokens. Its actual monetary charge was unavailable. These two samples indicate a narrower import improvement, not reliable skill performance or cost optimization.

After the skill was updated to prohibit the duplicate lookup button, one further trial built, passed cancellation and confirmation, and looked up the original request. Its recovery check still failed because the screen duplicated the status heading already rendered by `Receipt`; the last assertion remained unobserved. The model took 54.284 seconds and reported 82,837 input tokens, including 61,440 cached tokens, and 2,515 output tokens. Actual monetary charge was unavailable. The follow-up instruction against duplicating either control or heading has not yet been model-evaluated.

A no-model diagnostic removed only the duplicate heading from a copy of that answer and replayed the same browser scenario against the same SDK archive. All four assertions passed, including lookup and recovery. This isolates the observed failure; it is not an unedited model result or a new skill evaluation.

A subsequent single small-model trial using the updated build skill passed all four browser assertions without manual edits: the installed screen mounted, cancellation and confirmation produced the expected ledger, the original request was looked up after reopening, and the pending and resolved states were accessible. The skill read was observed. The attempt took 81.695 seconds of model time and 82.965 seconds including browser evaluation; it used 136,362 input tokens (115,968 cached) and 4,047 output tokens. Actual monetary charge was unavailable. This is one passing sample of the practiced scenario, not independent promotion evidence or an optimized cost result. The captured pending text also repeated the request identifier, which remains a copy-quality issue.

A single small-model data-row trial with the installed Web package passed its executable checks for order, zero and missing values, denied access and unchanged frozen input. The build skill read was observed. The attempt took 16.696 seconds and used 43,237 input tokens (27,776 cached) and 574 output tokens. The charge was unavailable. This checks a data transformation, not a rendered interface, and does not replace repeated or held-out skill evaluation.

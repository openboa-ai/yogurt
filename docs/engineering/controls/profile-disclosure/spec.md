# Profile details disclosure

Status: reviewed implementation scope under the owner-selected motion-led component foundation replacement. This change does not establish Native rendering or visual approval.

## Intent and boundary

Use the existing `DisclosureRow` for the optional details within `ProfileCard` so the ordinary disclosure behavior and its open/close motion have one implementation. The host retains the profile's `name`, `detail`, `initials`, `children` and `actions` and any actions' effects. Add `ProfileCard` to the ordinary package export without removing the existing motion entry or its registry wrapper. Keep existing props and callback behavior unchanged. The installed discovery catalog continues to advertise its existing motion entry; both imports resolve to the same implementation. No data, status or effect is generated by revealing content.

Preserve the collapsed initial state, the accessible summary name `More about {name}`, keyboard activation, native details semantics and content lifetime. The disclosure is absent when `children` is null or undefined. Preserve the existing card surface, 24 px corner and regular card inset. The summary uses the shared disclosure's 44 px minimum target, indicator and focus treatment. Remove the ordinary separator line; whitespace and the shared control convey the relationship. Details and host actions wrap within a narrow container.

Use the existing shared disclosure opening and closing behavior, including rapid reversal and reduced-motion fallback. Keep content available only while native details is open. Do not duplicate timers, create product state or introduce a new token for this one composition. Forced colors and keyboard focus remain visible.

## Required evidence

1. On the ordinary Web export and installed editable entry, verify profiles with and without optional details; preserve accessible name, text, actions and closed state. With keyboard and pointer, open, close and rapidly reverse the disclosure without duplicate effects or focus loss.
2. At 320 and 1440 CSS px in light and dark, verify long names, wrapped detail content and actions stay within the card, with no perimeter or separator line. Check open, close and reduced-motion outcomes; capture rendered states separately from DOM checks.
3. Confirm the motion guide uses the same exported `ProfileCard`, and run the shared disclosure and affected gallery tests. Report Web, installed-host and Native evidence separately; do not claim a Native implementation from Web results.
